# NapCat 接入

NapCat 是月璃最常用的协议端：支持平台多、社区大。
本篇从下载协议端一路做到 QQ 里收到回复。

**前置**：月璃后端已经能在本机跑起来（[第一次启动与配置](../deployment/first-run.md)），
并且准备了两个不同的 QQ 号——机器人号用**小号**。

## 第一步：装 NapCat

=== "Windows：用桌面控制台（推荐）"

    到 [NapCatQQ Desktop 的 Releases](https://github.com/NapNeko/NapCatQQ-Desktop/releases)
    下载 `NapCatQQ-Desktop-<版本>-x64.msi`，双击安装。

    **这不是协议端本体，而是它的管理器**：在这个窗口里就能装 QQ、装 NapCat、
    启动与停止、看日志、改配置，不用自己抠命令行。

    > 下载时注意：文件名带 `watch-v` 的是远端监控小工具，不是桌面安装包。

    要求 Windows 10 / Server 2016 以上、x64。安装后配置数据在
    `%ProgramData%\NapCatQQ Desktop`，重装不会丢。

    打开后按它的引导创建实例、装好依赖组件，把 QQ 和 NapCat 都启动起来。

=== "任意系统：Shell 包"

    到 [NapCatQQ 的 Releases](https://github.com/NapNeko/NapCatQQ/releases)
    下载 `NapCat.Shell.zip`，解压到一个**独立目录**——
    不要放进月璃的目录里，两者的升级节奏完全不同。

    - Windows 11：运行包内 `launcher.bat`
    - Windows 10：运行 `launcher-win10.bat`
    - Linux：按包内说明运行启动脚本

    这种方式需要自己准备与 NapCat 版本匹配的桌面 QQ。

更多的安装形态与注意事项以官方文档为准：
[NapCat 官方文档](https://napneko.github.io/)。

## 第二步：登录机器人 QQ

启动后按提示用**机器人小号**扫码登录，保持 NapCat 进程运行。

启动日志里会打印一个 WebUI 地址，用它打开 NapCat 自己的管理界面
（**这是协议端的面板，和月璃的管理面板是两个东西**）。登录后：

- 按界面要求设置或更新管理密码
- 确认页面上显示的 QQ 号就是你打算当机器人的那个小号

## 第三步：建一个正向 WebSocket 服务端

这一步是把「门」打开，让月璃能连进来。

在 NapCat WebUI 里打开**网络配置**，点新建，选择 **WebSocket 服务端**。

> 必须是「服务端」。选成「WebSocket 客户端」或只开 HTTP 服务端都不行——
> 月璃是主动去连的那一方。

同机部署照这一组填：

| 协议端这一项 | 填什么 | 月璃那边对应 |
| :--- | :--- | :--- |
| 启用 | 打开 | 插件连接段的 `enabled = true` |
| 监听主机 | `127.0.0.1` | `host = "127.0.0.1"` |
| 监听端口 | `8095`（示例） | `port = 8095`，两边必须一致 |
| 访问令牌 | 自定义，留空也行 | 有值就原样填进 `token` |
| 消息上报格式 | **`array`** | 适配器按消息段解析 |

!!! danger "messagePostFormat 必须是 array"

    这一项填成字符串格式（`string`）会让消息段解析失败，
    表现是**能连上但收不到正常内容**。改成 `array` 后重新启用服务。

保存后确认服务**真的开始监听**了——只保存草稿、没有启用，端口是不会开的。

跨机器或容器部署时，监听地址要允许月璃所在的机器访问，端口也要正确映射。
月璃那边填的是**连接目标地址**，不能填 `0.0.0.0`（那是监听范围，不是可达地址）。

## 第四步：在月璃这边选插件、填连接

编辑月璃项目里的 `config/adapter.toml`，指定用哪一个插件：

```toml
plugin = "yueli-napcat-adapter"
```

然后把连接配置写到这个插件自己的目录：
从[连接模板](https://github.com/YueLi-and-Me/YueLiBot/blob/main/config.example/adapters/yueli-napcat-adapter.toml)
复制一份到 `adapters/yueli-napcat-adapter/config.toml`，改下面这几个值
（**改已有字段，保留模板里的其他配置**）：

```toml
[napcat]
enabled = true            # 启用前先在协议端把正向 WS 服务端建好
self_qq = "123456789"     # 机器人小号，必须与协议端当前登录一致
host = "127.0.0.1"        # 协议端所在主机；只填地址，不带 ws:// 和端口
port = 8095               # 与协议端实际监听端口一致
token = ""                # 协议端设了访问令牌就填这里，没设留空

[owner]
qq = "987654321"          # 你自己的 QQ 号，与上面必须是两个不同的号
```

!!! warning "三个「令牌 / 密码」不要填混"

    - `token`：协议端**正向 WebSocket 服务端**的访问令牌，没有就留空
    - NapCat 管理面板的**登录密码**：只用于登录 NapCat WebUI，不填到这里
    - 月璃启动时终端打印的 **token**：用来访问月璃管理面板，与协议端无关

## 第五步：启动并确认

保持 NapCat 在线，在月璃项目根目录运行：

```bash
uv run bot.py
```

后端终端会打印适配器加载、协议连接结果和识别到的登录号。三项都对之后：

1. 用**你自己的 QQ** 私聊机器人号，发一句短消息
2. 确认 QQ 里真的收到了回复（不是只在月璃面板里看到）
3. 把测试群号写进插件配置的 `[group]` 名单，重启月璃
4. 在群里用 QQ 的 **@** 功能提及机器人，确认群里有回复

## 连不上的常见原因

| 现象 | 先查这里 |
| :--- | :--- |
| 连接被拒绝或超时 | NapCat 在跑吗、正向 WS 服务启用了吗、端口与配置里写的一致吗 |
| 握手返回 401 / 403 | `token` 填错了，或把管理面板密码当成访问令牌填了进去 |
| 握手失败、方法不可用 | 端口填成了 NapCat WebUI 或 HTTP 服务的端口，不是 WS 端口 |
| 报登录号不匹配 | `self_qq` 与 NapCat 当前登录的号不一致，或连到了另一个实例 |
| 连上了但消息解析报错 | 服务端的 `messagePostFormat` 不是 `array` |
| 你私聊有回复，别人的没有 | 私聊名单是白名单模式且没写他——这是默认的安全行为 |
| 群里 @ 了也不回 | 群号没进 `[group].list`；或她正在睡眠 |
| 找不到配置段 | 连接文件必须放在所选插件目录下，段名必须是 `[napcat]` |

**断线重连间隔与动作超时改不好这些问题。** 端口、令牌、账号错了，
把超时调多大都连不上；这两个参数只影响网络抖动时的表现。

**戳一戳要单独确认。** 它依赖连接后的能力探测，普通文字收发成功不代表它可用；
群里还要开启对应的动作开关。

**只想先看看配置对不对**，可以跑只读自检（见[适配器配置](../configuration/adapter.md)），
但它不替代真实的网络与投递验收。

配置能读通、连接能建立、QQ 真收到回复——这三件事要分别确认。
