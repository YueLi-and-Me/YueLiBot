# 屏幕感知

屏幕感知由两个**正交**开关控制，别把它们当成一回事：

- `[vision]` 管「看」：什么时候截屏、截什么、发给哪个模型。
- `[perception]` 管「说」：已经获得的屏幕情境，允许出现在哪些会话出口的提示词里。

默认状态：`vision.enabled = false`、`vision.chat_image_enabled = false`、`perception.surfaces = ["desktop"]`。
依赖：截屏只发生在桌宠外壳里，所以桌面屏幕视觉还要求 `desktop_pet.enabled = true`；
两类视觉功能都要求 `models.toml` 的 vision 任务档配好带视觉能力的模型，否则配置加载期直接报错。

## 什么时候会截屏

屏幕视觉（`vision.enabled`）打开后，截图只在这几种时刻发生——她不会持续盯着你的屏幕：

- 你在桌宠窗口说的话里提到屏幕（「看看我这个报错」「我在干嘛」这类意图由桌面端本地规则判断）；
- 你在托盘菜单打开「持续看屏幕」（该状态不落盘，重启即关）；
- 桌面主动搭话的「场景」意图触发时，先瞥一眼再决定说什么。

截图按 `capture_mode` 执行：`window`（默认）只截前台那一个窗口，拿不到前台窗口标题就跳过本次；
`screen` 截整个主屏，会连带桌面、任务栏和其他窗口。所有截图在内存里缩放到 768×432 以内的 JPEG 发给视觉模型，**不落盘**。
扫视有 20 秒冷却与 60 秒缓存：短时间重复触发会复用上一次结果。

`fullscreen_silent`（默认开）只管一件事：检测到疑似全屏窗口时压制**主动搭话**，避免直播、录屏把她的话收进去；
它不拦截你主动发起的屏幕问答。

## QQ 聊天图片是独立开关

`vision.chat_image_enabled` 控制「QQ 聊天图片是否调视觉模型描述」，与桌面屏幕视觉互不影响：
开任一者即要求 vision 任务档可用。图片描述失败时保留 `[图片]` 占位，她不猜内容。
表情包入库打标签、内容审核也复用这个任务档，见[表情包](emoji.md)。

## 感知出口：屏幕情境允许在哪说

`perception.surfaces` 决定提示词里的「前台活动」块（前台程序、持续时间、屏幕描述）允许注入哪些出口：

- 可取值只有 `desktop`（桌宠窗口）与 `direct`（QQ 私聊）；默认 `["desktop"]`；空列表表示任何会话都不注入。
- 只对**你（主人）**生效：群友私聊她也不会注入。
- `direct` 出口只能用既有缓存描述（60 秒内有效）——QQ 侧没有触发截图的链路，截屏始终发生在桌面端。
- 另注意：桌面主动搭话的措辞不受 surfaces 约束（它本来就只投放到桌面出口）；surfaces 管的是聊天提示词里的活动块。

## 群聊为什么是结构性排除

`group` 不是「默认关闭」，而是**不存在这个选项**，三层结构保证：

- 配置层：surfaces 里填 `group`，配置加载期直接报错，起不来。
- 提示词层：活动块的唯一注入点按会话类型判定，群聊类型必然不命中。
- 主动搭话层：只投放到桌宠会话，结构上够不到群聊。

屏幕内容是你机器上最私密的数据之一，把它限定在「你本人 + 桌面/私聊」是有意的边界，不要试图绕开。

## 你问屏幕内容时的完整链路

以桌宠窗口为例：你的消息发出前，桌面端本地规则判断是否在问屏幕；命中就先截一帧发给视觉模型
（只用程序名做先验，窗口标题不进模型请求），模型返回一句不超过 30 字的描述，
随后的回复就把「刚瞥了一眼」作为上下文。认不出时提示词要求她直说，并明确禁止拿以前看到的画面充数。

## 怎么开、怎么关、失去什么

- 开屏幕视觉：`features.toml` `vision.enabled = true`，配好 vision 任务档；`vision.enabled`、
  `fullscreen_silent`、`capture_mode` 改动需重启后端。
- 开 QQ 图片描述：`vision.chat_image_enabled = true`，不需要桌宠。
- 调整开放范围：`perception.surfaces`，例如加 `direct` 让你在 QQ 私聊里也能问「我在干嘛」（用缓存描述）。
- 全关：两个 `enabled` 保持 false、surfaces 留空。失去的是：她看不懂你发的图片、
  不知道你前台在干嘛、主动搭话失去「场景」这类由屏幕触发的由头。表情包入库打标签也会因拿不到视觉模型而停摆。
