# 黑话词表

她从会话里学来的「这群人才懂的说法」及释义。学词的机制见
[core-agent 模块](../../dev/modules/core-agent.md)；一次真实的学词过程在
[会话观察](observe.md)的事件账本里能看到：黑话提取、黑话推断、黑话命中三类事件
分别对应证据收集、含义判定与回复时的查表命中。

## 列表

词条行从上到下是：词条本体、范围（「全局通用」或具体会话）、命中次数、出现次数、
入库时间、来源标签，以及释义全文。两个计数的口径不同：

- **命中**：回复时查这张表的命中次数，含被跨轮去重排除、被条数上限截掉的判定，
  只反映查表频率，不是实际注入条数。
- **出现**：学习期在语料里见到的次数。

来源标签区分「在线学习」与迁移带入的存量；迁移条目在来源上单独标注。

## 复核

三个页签各是一种状态：**已确认**（进入注入）、**待定**、**已驳回**（判定「这不是
黑话」，退出注入）。默认显示已确认页签。待定页签里有两类条目：尚未攒够证据的
「待判定」，和推断过、群内用法与通用含义一致的「判定为普通词」——后者有些来自
名字守卫把疑似人名批量降级的结果。

行内与批量是同一套动作，各管一件事：

- **确认**：判定这是黑话，进注入。确认会锁定自动推断，证据继续增长也不会把人工
  结论覆盖回去。
- **驳回**：判定这不是黑话，退出注入但保留行；学习器再遇到同一个词只累加证据、
  不会重新插回待定。撤销驳回则解锁，把词交回自动判定。压制一个真实存在但不该
  注入的词用驳回。
- **删除**：不可逆移除；同一个词日后会作为全新候选重新入库，从待定重走一遍判定。
  清理误抽取的噪声用删除。

「全选本页」勾选后，批量确认 / 批量驳回 / 批量删除在顶栏出现，按钮上标注影响
条数。

## 筛选与排序

- **范围**：全部词条、仅全局通用、仅某条会话三档。
- **关键词**：匹配词条或释义，提交式（回车或点「搜索」）才发请求。
- **排序**：默认按入库时间倒序（后学到的在前），可切换按命中次数排；两个按钮
  再点一次都翻方向。列表分页。

页签、范围、关键词三个条件是叠加的：先按状态页签分堆，再套范围与会话过滤，最后
在结果里匹配关键词。换任何条件都会回到第一页。

## 生效范围

召回已接入行动决策与回复生成两级：确认过的词条按会话范围注入对应提示词。全局
词条在任何会话都生效；会话级词条只在匹配的那条会话生效。范围在学习判定时就已
确定，复核动作改的是「进不进注入」，不是范围。新部署的库词表为空，学词服务在
后台积累证据、按阶梯阈值自动判定，人工复核只是它上面的一层修正。

自动判定的方向：证据攒够时按群内用法与通用含义的差别判「是黑话」或「普通词」，
两条路都会写进释义。人工的确认与驳回直接锁住这一层——想让某个词无论证据多少都
不再变来变去，确认或驳回一次即可。

释义本身是推断链的产物：先在上下文里解释一遍，再脱开上下文解释一遍，最后对比
两种含义决定判定。事件账本里的黑话推断事件会展示这三段结果，看不懂某个词条为什么
被判定时去那里翻原始依据。
