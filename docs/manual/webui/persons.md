# 人物与关系

她记住的每一个人在这里有一份独立画像：平台身份、好感度、同框过的群、以及关于这个
人的事实记忆。事实的修改与裁决在[记忆管理](memory-manage.md)页，本页只看。身份
如何从消息里归并到人，见[平台抽象与适配器](../../dev/architecture/platform-io.md)。

## 人物列表

每行一位人物，默认按好感度从高到低排，表头可切换按事实条数或最后互动时间排：

- **显示名**：她的画像里这个人的名字。
- **平台身份**：来源平台的标识，如 `qq:114514`。
- **同框的群**：和她在哪些群同时出现过，附群数。
- **好感度**：0 到 100 的当前值，随互动漂移，机制见
  [记忆系统](../../dev/architecture/memory.md)。
- **事实**：关于这个人的有效事实条数；悬停可见含已冻结的总数——冻结的还留着，
  只是不再参与召回。
- **最后互动**：最近一次同框时间。

列表分页，底部显示总人数与页码。

## 人物详情

点任意一行进入单人画像，三个分区：

- **关系状态**：好感度数值与进度条，以及画像最近更新的时间。
- **身份与会话**：认识时间、画像更新时间，身份标签组，以及这个人出现过的会话
  出口。身份标签的拆法：QQ 身份拆成「QQ昵称」与「QQ号」两片，避免昵称与账号
  混在一片里难认；其它平台合并为「平台 / 昵称 · 外部标识」。群成员关系按群单独
  成片，展示该人在群内的群名片，没设置群名片的显示占位文案。
- **事实记忆**：该人物全部长期事实的表格，列为内容、类型（身份 / 事件 / 偏好 /
  习惯 / 关系 / 状态）、保留度、复习到期、状态。整行变淡的是已冻结条目，原文
  不改写；冻结与恢复的操作在[记忆管理](memory-manage.md)页完成。

「身份与会话」卡里两个时间字段容易混：**认识时间**是这个身份第一次出现、建档的
时间，此后不变；**画像更新时间**是好感度或事实最近一次变动的时间，随互动推进。
前者回答「认识多久了」，后者回答「最近还熟不熟」。两个时间都以面板统一的时间
格式显示，精确到秒。

事实类型是后端抽取时打的分类标签，决定衰减节奏与槽位裁决的粒度；保留度随时间
下降，「复习到期」是这套巩固机制安排的下一次复习时间点。

## 隐私与可见范围

事实正文是记忆抽取留下的原文，面板不做脱敏——能打开面板的人都能看到全部人物
画像。这与面板只监听回环地址的设计相配：本机自己看，远程走 SSH 隧道，见
[无头部署](../deployment/headless.md)。

## 空库是什么样

刚部署还没有会话数据时，人物列表为空，只显示空态提示；有会话流入并跑过记忆抽取
后，第一批人物画像才出现。消息必须先被归属解析绑定到人，才会在列表里冒出新行；
同一个人换了昵称不会另立新行，平台身份相同就还是那份画像。

## 从别处跳进来

人物页不是唯一入口：[会话观察](observe.md)的会话状态卡把当前会话出现的人物列成
链接，点击直达详情；[记忆管理](memory-manage.md)按人过滤事实，与本页详情共用
同一份人物清单。详情页有稳定的地址（`/persons/` 加人物 ID），直接输入或收藏
深链都能打开，刷新不丢页面。
