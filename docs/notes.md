# 设计决策与踩坑

按「为什么这么写」组织。多数条目背后是实测数据或一次真实的翻车。

其中标 ⚠ 的几条**没有任何报错**，只表现为「功能不工作」——不知道的话能查很久。

---

## 一、AI 立绘

### 不用 LoRA + inpaint 那套

2023 年的工作流（训 LoRA、画遮罩、ControlNet、提示词权重）门槛高得劝退。指令式编辑模型已经把这一环铲平了：传底图 + 一句「保持一致，只改表情」即可。

所以管线的用户输入只有两样：**参考图 + 一句角色描述**。16 种表情的中文指令模板写死在 `scripts/sprite/config.ts`，使用者不必碰。

### 模型选型：一致性 > 速度

同一组「只把帽子改成红色」的指令编辑：

| | Seedream 4.0 | **5.0 Pro** |
|---|---|---|
| 单张耗时 | 5–7s | 62–67s |
| 宽度漂移 | +43px (3.4%) | **-3px (-0.3%)** |
| 高度漂移 | +21px (1.0%) | **0px** |

慢 10 倍换零漂移。一致性是素材质量的天花板，速度只是等待时间。

管线**按阶段自动换档**：底图候选用 4.0（本来就要 4 张各不相同的图，一致性毫无意义），表情差分用 5.0 Pro。

### ⚠ 「差异 12% 但我看不出来」

用户实测反馈。第一反应是整体位移（肉眼无感但会把整条轮廓标红），改用暴力搜索最优对齐后发现：**最优位移就是 (0,0)，没有位移**。

真相是模型把角色**整个重画了一遍**——设计、姿势、服装都保住了，但布料褶皱、发丝走向、尾巴形态全部重绘，身体区域差异 18~20%。

静态对比看不出来是正常的（人眼对「同款不同笔触」不敏感），但人眼对**闪变**极其敏感。整图切换表情时整个身体会「滋啦」一下。

**解法：脸部烘焙。** 后处理阶段把所有表情的脸贴到同一具身体上，用羽化椭圆遮罩融合（硬边会在交界处露接缝）。烘焙后身体逐像素一致，切换零闪烁。

实测：身体差异 18~20% → **0.0%**，只剩头部 1.1~2.8%。

### ⚠ 五官自动检测会被长发打败

检测原理是求差分图之间的差异区域。但 `eyes/x` 是从 `face/x` 编辑出来的，**它的身体同样会被重画**——而身体面积远大于眼睛。

实测一个及腰长发角色：「眼部」差异峰值落在 y=711（34% 高度处，胸口位置），眼睛的信号完全被淹没。检测吐出 347×474 的「嘴区」和 192×335 的「眼区」。

**这种结果比没有更糟**——硬用会让烘焙把大半个角色换掉。所以加了 `plausible()` 兜底，不合理就丢弃并跳过烘焙，让人手填 `--face`。

两道防线仍然值得有（只在头部搜索、找最密集的一块而非所有差异的包围盒），但**别指望自动检测百分百可用**。

量坐标时注意：**脸不一定在画布中心**。头发向一侧铺开会把内容包围盒的重心带偏（实测偏了约 60px）。

### 隐私：窗口标题绝不外传

窗口标题里什么都有——文件路径、客户名、聊天对象、账号后四位。它对「她该说什么」的增益微乎其微：知道「他在工作」就够劝他休息了，知道他在改 `payroll_2026Q3_final.xlsx` 不会让这句关心更好。

`core/awareness/classify.ts` **吃掉标题、只吐类别**。标题唯一的用处是本地判断浏览器在干嘛，判完就丢。

时长也写成模糊区间：「两个多小时」而不是「137 分钟」——后者会让她像个监控软件。

## 二、对话

### ⚠ 深度思考是延迟灾难

方舟的「快」模型反而慢 10 倍，因为默认开思考：

| 模型 | 开思考 | 关思考 |
|---|---|---|
| `seed-2-1-turbo` | 30992ms | **3664ms** |
| `seed-2-0-lite` | 26597ms | **3189ms** |
| `seed-character` | — | **2404ms** |

它要先写几百字思维链才开口。桌宠场景里等 30 秒等于产品报废，所以**默认关闭**（`LLM_THINKING=disabled`）。

角色扮演专用模型 `doubao-seed-character-*` 最快且人设质量最好。

### 输出协议用 XML 而非 JSON

唯一原因是**流式**：半截 JSON 是非法的，只能等整段收完才能 parse，那会造成 2–3 秒死寂，陪伴感当场归零。标签可以边收边解——`<say>` 开标签一出现就立刻切表情并开始逐字输出。

`core/agent/parser.ts` 是个增量状态机，必须扛住：标签被网络包切断、模型完全不按格式吐纯文本、漏写 `</say>`、思维链混在正文里。

### 存历史存原始标签，不存提取出的台词

模型看到自己上一轮的标签输出，下一轮才会继续遵守格式。

### ⚠ 模型几乎从不输出 `<mood>`

提示词写「只在情绪确实有波动时才输出」，模型基本不认为够格。结果是聊了几十轮人格数值一动不动，性格漂移整条线废掉。

所以加了 `applyTurn()`：**聊天本身就推进关系**，`<mood>` 只是在此之上加码。幅度刻意很小，靠量变累积。

## 三、记忆

### 中文检索不需要编译型扩展

`simple` 之类的 FTS5 中文分词器是 C 扩展，要按平台分发 `.dll`/`.so`，还要求 `better-sqlite3` 开启扩展加载。对打包给普通用户的桌面应用是分发噩梦。

改用**预分词 + 原生 `unicode61`**：`Intl.Segmenter`（V8 自带 ICU，零依赖）切词写进索引列。

但它对中文有真实误分：

```
不喜欢吃香菜   → 不 / 喜欢 / 吃香 / 菜     应为 吃 / 香菜
月璃穿了连衣裙 → 月 / 璃 … 连 / 衣裙       专名和复合词都拆错
```

**兜底是同时索引字级 bigram**：`吃香菜` 的 bigram 含 `香菜`，自造的名字 `月璃` 本身就是一个 bigram。bigram 检索是中文 IR 里公认可靠的基线，配上分词等于双保险。

验证（真实 SQLite，非模拟）：误分的「香菜」「月璃」「连衣裙」全部能召回。

### 检索用 OR 而非 AND

记忆检索要的是「相关」不是「全命中」。用户问「我上次说的那个香菜」，「上次」「那个」都不在任何记忆里，AND 语义会全部落空。

### 遗忘曲线：双阈值滞回

```
retention = strength × 2^(-已过小时 / 半衰期)
freeze 0.10 → 转非活跃（不删除）
revive 0.15 → 必须回升过此值才重新激活
```

单阈值会让记忆在边界反复闪进闪出。另外**预计算下次穿越阈值的时刻**（`due_at`），到点才评估，不用周期性全表扫描。

半衰期按类型分档：身份/日期按年，偏好按季度，临时状态 12 小时。用同一个半衰期的话，「他不吃香菜」会隔天就忘。

### 永不删除

非活跃记忆照样参与检索。玩家主动提起时她能想起来——这个「啊我记起来了」的瞬间比一致地记得更有说服力。

### `recall_cues`

L2 摘要时额外生成「什么情景下会需要这条记忆」的自然语言线索，**检索匹配 cue 而不是摘要本身**。

摘要写「发生了什么」，查询问「我现在想找什么」，两者措辞天然不一致。

## 四、人格

### ⚠ 数值绝不进 prompt

写「亲密度 73」进去，模型会开始扮演「一个亲密度 73 的角色」，输出里冒出「（好感度+2）」这种破戏的东西。

必须翻译成自然语言的**行为指令**：「你现在对他很依赖，说话会不自觉撒娇」。单测里有一条断言描述文本不含任何数字。

### 连续轴而非离散路线

「可爱/傲娇/病娇」这样的离散路线一旦选定就锁死，玩家能感觉到自己在走剧本。四条连续轴（亲密度、傲娇度、依赖度、精力）让变化是渐进的、没有明确分界的。

## 五、Electron 的坑

这一节全是 ⚠。它们的共同点：**没有任何报错**。

### `focusable: false` 会让窗口收不到任何键盘输入

本意是「点她时不抢走你正在打字的窗口的焦点」，结果是输入框弹出来却打不进字，Escape 也失效，于是它卡在那儿关不掉。

正确做法：`focusable: true` + `showInactive()`——显示但不夺焦点，需要打字时才主动 `focus()`。

### `setPosition` 在非整数 DPI 下每次调用撑大窗口 1px

150% 缩放下实测：60 次调用把窗口从 `460×501` 撑到 `520×561`。拖动是每 16ms 一次，几秒就肉眼可见。窗口撑到撞上屏幕边缘后被 Windows 钳制，表现为「贴近右边会自动缩进」。

根因是 DIP↔物理像素换算的舍入累积（该机逻辑分辨率 1707×1067，因为 2560/1.5 = 1706.67 自带小数）。

**解法**：拖动用 `setBounds` 并显式钉住 `width`/`height`；起始 bounds 只在按下时读一次，之后每帧从它算目标，**绝不读回**——读回会把上次的舍入误差带进下一次。

### ESM preload 需要 `sandbox: false`（踩了两次）

`.mjs` preload 只有关掉 sandbox 才会被加载。开着的话 **preload 静默失败**，`window.pet` 不存在。

第一次表现为「点击穿透永远开着，角色完全点不到」；第二次（日记窗口）表现为「日记永远显示还没有记下什么」。

`contextIsolation` 仍然开着，安全边界没塌。

### 点击穿透的命中检测必须包含 UI 元素

窗口默认整体穿透，只有命中检测说「在角色身上」才恢复接收事件。而**输入栏在窗口左侧的透明区域，那不是角色像素**——光标一移上去窗口立刻恢复穿透，点击穿到桌面，输入框根本点不到。

解法：给需要交互的 UI 打 `data-hit` 标记，命中检测用 `elementFromPoint(...).closest('[data-hit]')` 一并认。

### 拖动不能用 `-webkit-app-region: drag`

它会把整块区域变成拖拽把手，点击事件就不可靠了。而角色身上既要能拖又要能点，靠 4px 位移阈值区分。

另外必须 `setPointerCapture`——拖到窗口外也要收到 up 事件，否则松手时窗口会「粘」在光标上。拖动过程中命中检测要暂停，不然光标一离开轮廓窗口就恢复穿透、直接收不到松手。

### Vite 默认绑 IPv6

`localhost` 在 Windows 上解析成 `::1`，只监听 IPv6 回环。部分环境不允许连 `::1`，表现为「ready 了却连不上」，在 Electron 里就是**窗口一片空白**。显式绑 `127.0.0.1`。

### 多入口必须在 `rollupOptions.input` 里列全

dev 模式下 Vite 会即时编译任意路径，所以「忘了列 `diary.html`」只在打包后暴露成 404 白窗口。

### `requestAnimationFrame` 在页面不可见时不触发

两次踩到：

1. 测试渲染层时 rAF 是 0 fps，测出来的结果全是空气
2. **口型驱动用 rAF 是设计错误**——音频在页面不可见时不会暂停，而 rAF 会停。她说话中途被收进托盘再拿出来，嘴会僵在上一帧的开度上，跟正在播的声音完全脱钩。改成 50Hz 定时器

## 六、自检哲学

**报一个假的通过比不报更糟。**

写自检时踩过两次：

- 隐私断言原本拿实时窗口标题比对，但取不到标题时 `title.length > 4` 不成立，断言自动为真——什么都没证明。改成**注入**一个敏感标题当探针
- 做梦断言把正确行为报成失败：自检一天跑几次，「一晚一个梦」的去重正确拦住了第二次，可断言只认「这次新生成了」

还有一条：**探针不能自己复现它要检出的 bug**。窗口移动探针原本用 `setPosition`，而那正是漂移的来源。

单测里带 ★ 的条目是「这条挂了说明核心设计不成立」，不是普通回归。

## 七、视觉感知

### 游戏事件不参与四小时去重

Steam 游戏时长会随着游玩增长、每次描述也会换措辞，所以要按游戏名做四小时去重；
资源管理器的提示是固定泛化文字，也应低频去重。但游戏死亡、胜利或任务失败本来就会
反复发生，`game-event` 不写入这份去重状态。它仍受主动打扰预算的 30 分钟冷却约束，
不能为了防刷屏再叠一层四小时静音。

### 游戏事件与场景按触发路径分档

`frame-change` 会问刚才发生了什么，只接受 `GAME_EVENT`；`idle-glance` 则问这幅画面
里有什么值得随口提一句的状态、规模、反差或时间点，产出 `GAME_SCENE`，但也允许正好撞上
结算时的 `GAME_EVENT`。上下文校验仍然严格：游戏窗口只收这两种类型，Steam 和资源管理器
各自只能收自己的类型，意图层的宽松不能越过这条隐私边界。

### 快慢节奏游戏不需要名单

快节奏游戏的帧变化经常触发 `frame-change`，它会更新该场景的 `lastCallAt`，因此闲时瞥很少
出现，角色自然更关注事件；慢节奏游戏则主要等到 `idle-glance`，自然更关注场景。这是刻意
保留的无名单品类路由：不要为「快游戏没有 scene」增加游戏列表、per-context 阈值，或调整
`FRAME_CHANGE_THRESHOLD`。事件不参与持久化去重，场景按归一化游戏名去重一小时；两者仍都
受主动搭话预算限制。

### 睡眠状态只从主进程流向渲染层

`SleepStateController` 是 daily 日程的唯一访问器，并把基础睡眠状态和十分钟的被叫醒宽限期
合并。主动感知的既有 tick 负责在变化时推送 `{ asleep }`，渲染层只切 `sleepy` 立绘，从不读
时钟或日程；用户点角色、从托盘发起对话或发送消息都会延长清醒状态。对话表情在六秒后回落时
同样读取这份状态，避免她说完一句话就从 `sleepy` 错切成 `normal`。

### ⚠ 标题匹配失败绝不退回全屏截

`captureWindow()` 只能截到与前台标题匹配的窗口时才返回截图。匹配不到宁可不看；退回
全屏会把第二显示器、后台聊天或银行页面一并送上云，这条红线由自检的
`refusesWhenTitleUnknown` 钉住。

### ⚠ 提示词不是隐私边界

视觉模型被要求忽略密码、路径和私人信息，但模型输出永远不能当安全保证。
`sanitizeVisionDescription()` 才是最后一道本地收口：它拒绝敏感词、路径和超长数字；
放宽它来迁就模型输出，等于放弃这条隐私边界。

## 八、被放弃的方向

### Live2D

原计划作为占位先跑通。但 `texture_00.png` 已损坏——**全文件被 UTF-8 解码替换，含 1274 万个 U+FFFD**，PNG 签名首字节 `0x89` 被换成 `EF BF BD`，不可恢复。多半是传输时按文本模式处理过。

而 AI 立绘差分这条路已完整跑通，Live2D 不再必要。`CharacterView` 抽象还在，将来真要加也只是新增一个实现类。

顺带：Cubism SDK 商用分发需要 Release License，走 AI 立绘后这条约束自然消失。

### 方舟 TTS

方舟**没有** OpenAI 兼容的 `/audio/speech`（实测 `audio/speech` 和 `tts` 两个路径都是 404），它的语音合成是独立服务、另一套凭证，没法复用 `ARK_API_KEY`。

所以整条语音链路做成**可选**：`TTS_ENABLED=0` 时纯文字，其余功能不受影响。客户端那半边（队列、缓存、口型、打断）是厂商无关的，已完整实现并验证。

## 九、生成式生活

### 每天一份计划，失败时回到固定表

`DayPlanService` 在首次被需要时才生成并以本地日期持久化；同一天的并发请求共享同一个
inflight promise，生成失败或本地校验拒绝时写入固定 `SCHEDULE` 的等价计划。这样计划不会在
对话中途变来变去，也不会因为模型故障让角色失去“正在做什么”。过去日期只读取已经保存的
计划，缺失时用固定表补叙，绝不为离线叙述倒推生成历史。

### 入睡是平滑概率带，不是时钟阈值

睡眠状态用 bedtime 倾向、精力、最近互动和按日期稳定的微小抖动组合成 `probability`。刚聊天会
延后，低精力会提前；真正睡着后的醒来门槛更低，形成迟滞。`drowsy` 是介于清醒和入睡之间的
可观察阶段，日程描述会提示“再待十分钟就睡”，而渲染层仍只消费主进程推送的 `asleep`。

### sleepy 只是面部差分，不存在睡衣素材

已核对 `assets/character/yueli/manifest.json`：`sleepy` 只指向 `face/sleepy.png`，底图仍是同一张
`base.png`。因此此前把睡眠验收截图描述成“睡衣”并不准确；本轮之后只报告已核实的“闭眼/困倦
面部差分”，不会把未验证的服装变化写入结果。

### 场景观察为事件让出视觉额度

场景观察仍使用原有 15 秒轮询和每日视觉预算；当当天剩余额度只够两个事件时，普通场景观察会
让出额度，保留给游戏胜负、战斗和场景切换等事件，不新增定时器或后台截图频率。

## 十、睡眠周期必须同时有入睡端和起床端

`DayPlan` 的 `bedtimeHint` 与 `wakeHint` 共同定义一次睡眠倾向。睡意由接近就寝时上升和接近
起床时下降的两个 sigmoid 相乘得到，二者都锚定为真实的本地 `Date`，不再用 ±12 小时环绕
距离。实际晚睡会把自然醒倾向向后补偿一部分，精力不足也会赖床；实际入睡时刻写入本地状态，
重启不会丢失。迟滞仍负责防止清晨在阈值附近反复醒睡。

空档精力结算按计划睡眠窗口分段积分：睡眠小时恢复、其余小时消耗。最后 48 小时逐窗口计算，
更早部分沿用原来的瞬时状态近似，避免为了长时间离线逐日推演。

### 周期性状态机的验收规则

任何周期性状态机都必须扫描完整周期。睡眠曲线固定从当天 20:00 扫到次日 20:00，每十分钟
取一点，并检查相邻概率变化；只验证睡前到凌晨这一段，不能证明早晨的起床端连续。

## 十一、睡眠 hint 是状态穿越时刻

`bedtimeHint` 和 `wakeHint` 表示状态实际切换的倾向时刻，不是 sigmoid 的概率中点。入睡端按
`cutoff`、醒来端按 `WAKE_HYSTERESIS`，通过 `logit` 反函数和同一个 sigmoid 时间尺度动态
推导锚点补偿；门槛或曲线尺度变化时，不需要同步维护魔法分钟数。迟滞方向与双端相乘结构保持
不变。

赖床按“实际已睡时长与计划睡眠时长的缺口”计算。晚睡造成缺口时，只补偿其中一部分到自然醒
目标；当前精力不再承担这项判断，避免精力在夜间恢复到 50 后让分支永久失效。

日程生成会同时看到前一天的 `bedtimeHint / wakeHint`，并明确要求连续日之间出现早睡、熬夜或
睡懒觉等节奏方差；校验层只守安全和 4–18 小时睡眠窗口，不在模型输出后随机改时间。
若模型把多个 slot 错写成同一对象里的重复键，只允许一次不携带失败原文的协议修复重试；
第二次仍无效就按原规则持久化固定表回退，不能无限重试或放宽结构校验。
`schedule:selftest` 顺序生成连续七天，再对前三天每十分钟推进一次精力和睡眠状态，固定检查
状态切换、hint 偏差、跨日方差与完整曲线连续性。
