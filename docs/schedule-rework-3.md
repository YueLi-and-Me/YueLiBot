# 第六轮：睡眠时刻的校准与日程方差

第五轮**核心问题真的修好了**，我独立跑了三天连续模拟（精力随睡眠状态自洽演化）验证：

```
7/16 00:00 入睡 p=0.707  →  09:30 自然醒 p=0.182
7/16 23:50 入睡 p=0.782  →  09:00 自然醒 p=0.185
7/18 00:30 入睡 p=0.770  →  08:50 自然醒 p=0.206
相邻最大跳变 0.0630        晚睡 2h → 自然醒 +60min
```

三天入睡与醒来时刻各不相同、无环绕折返、无固定闹钟。两端 sigmoid 相乘 +
`cycleBoundary` 放在双方概率都近零处切换，这个结构是对的，**不要再动它**。

这轮是校准和方差问题，都不是结构性的。

## P0-1 · `hint` 和实际发生时刻差 40~53 分钟，早间日程被吞掉

### 问题

迟滞门槛和概率中点不是同一个点，导致 `bedtimeHint` / `wakeHint` 系统性失真：

- **醒来**：`wakeFall = sigmoid((effectiveWakeAt - now)/42)`，在 `effectiveWakeAt`
  这一刻 `p ≈ 0.5`，但醒来要求 `p ≤ WAKE_HYSTERESIS = 0.22`
  → `sigmoid = 0.22` 解出 `now = effectiveWakeAt + 53 分钟`
- **入睡**：入睡要求 `p ≥ cutoff ≈ 0.72`
  → `now = effectiveBedtimeAt + 40 分钟`

实测吻合：`wakeHint 07:30` 的那天，她 **09:00** 才醒。

### 为什么这是个真问题

不只是数字不好看。`DayPlan` 的 `slots` 是模型按 `wakeHint` 编的，
会出现「07:45 在吃早饭」这种时段——**而她要到 08:25 才醒**。
第四轮特意做的「睡着时日程描述不与普通活动矛盾」会把这些时段整段吞掉，
**生成出来的早间日程等于虚构**，模型写了、用户永远看不到。

`bedtimeHint` 同理：计划 23:30 睡，实际 00:10 才睡着。

### 改法

让 `hint` 表示**实际发生的时刻**，而不是概率中点：把两端锚点各自预补偿一次
门槛偏移——`effectiveWakeAt` 提前约 53 分钟，`effectiveBedtimeAt` 提前约 40 分钟，
使 `p` **穿越门槛**的时刻落在 hint 上（状态修正仍在此基础上叠加）。

补偿量要从 `WAKE_HYSTERESIS`、`cutoff` 和 sigmoid 分母**算出来**，不要写死常量
——否则以后调这三个数里的任何一个，偏移会悄悄回来，而且没有任何断言会红。

### 验收断言

```
★ 零状态修正下，实际入睡时刻落在 bedtimeHint ±10 分钟内
   energy=50、无互动、jitter=0.5 → 入睡时刻 ≈ bedtimeHint

★ 零状态修正下，实际自然醒时刻落在 wakeHint ±10 分钟内
   同上 → 醒来时刻 ≈ wakeHint

调整迟滞门槛后偏移不会重新出现
   把 WAKE_HYSTERESIS 改成另一个值，上面两条仍然通过
   （即补偿是算出来的，不是写死的）

第五轮的连续性不被破坏
   完整周期相邻 p 变化仍 ≤ 0.25
```

第三条是防回归的关键——**它能验证补偿是推导出来的还是拍脑袋填的。**

## P1-2 · 「没睡饱会赖床」是死代码

```ts
const wakeEnergyDelay = Math.max(0, energyShift)   // energyShift = (50 - energy) * 1.8
```

要它生效，需要在**接近起床时刻**精力仍低于 50。但精力在睡眠中以 `+4/h` 恢复：
带着 `energy = 37` 入睡，约 3.25 小时后就越过 50，此后 `wakeEnergyDelay` 恒为 0。

我那三天模拟里，醒来时精力分别是 74 / 82 / 84 —— **这一项从来没有触发过。**

这和之前抓到的 `IDLE_GLANCE_AFTER_MS` 是同一个形状：常量在，逻辑在，
但正常路径上永远进不去。

### 改法（二选一，倾向前者）

- **按「已睡时长 vs 应睡时长」赖床**：睡够了就醒，没睡够就拖。
  这才是「没睡饱」的字面意思，也天然处理「凌晨三点才睡」的情况。
- 或者保留精力口径，但改成用**入睡时刻的精力**（存下来）而不是当前精力。

无论选哪个，**必须有一条断言证明它在正常路径上会触发**，
不能只测「传一个极端值进去它会返回非零」。

```
★ 睡眠时长不足时会推迟自然醒，且这条在正常演化中真的会发生
   模拟一天：很晚才入睡 → 醒来时刻明显晚于 wakeHint
   （不是构造极端参数，是跑完整流程）
```

## P1-3 · 生成出来的日程方差太小

第五轮真实生成的三天：

```
23:40 / 08:25      23:15 / 07:30      23:42 / 07:25
```

就寝时间只在 **23:15–23:42** 之间波动，27 分钟。睡眠时长 8:45 / 8:15 / 7:43。

**这仍然是流水线，只是抖动幅度从 0 变成了半小时。** 用户要的是
「今天睡懒觉、今天熬夜、今天出门了一整天、今天什么都没干」——
需要偶尔出现 01:30 睡、偶尔 21:30 睡、偶尔睡到中午。

### 改法

- 提示词里明确要求**跨天的方差**，并给出具体范围的例子（偶尔熬夜到凌晨一两点、
  偶尔累了很早睡、偶尔睡到中午），而不是只说「每天要不一样」
- 把**前一天的 `bedtimeHint` / `wakeHint`** 也作为生成输入
  （现在只传了 `theme`），并明确指示：连续两天不要落在相近的时间
- 校验层放宽到能容纳这些情况（现在的 4–18 小时窗口够用，确认别再收窄）
- **不要用代码强制打散**（比如随机加减一小时）。那是在生成之外又叠一层规则，
  会和模型的意图打架。要让模型自己产生方差。

### 验收

生成**连续七天**并贴出 `bedtimeHint / wakeHint / theme` 表格。
判据：就寝时间跨度至少覆盖两小时，且至少出现一天明显反常（很晚或很早）。
七天全挤在半小时内 = 没做到，**先报告，不要自己加随机数糊过去**。

## P1-4 · 把这轮的验证方式固化下来

我这两轮抓到的问题（11:30 硬跳变、40~53 分钟偏移、赖床死代码），
**都是靠「三天连续运行 + 精力自洽演化 + 逐点扫描」量出来的**，
不是靠读代码看出来的。这个方法应该进代码库，别每轮靠人工重来。

加进 `schedule:selftest`：

- 连续运行 **≥ 3 天**，精力按睡眠状态自洽演化（睡 `+4/h`、醒 `-2/h`）
- 输出每次入睡/自然醒的时刻、当时的 `p` 和精力
- 断言：相邻 `p` 变化 ≤ 0.25；三天的入睡时刻**不完全相同**；
  三天的醒来时刻**不完全相同**
- 断言：实际入睡/醒来时刻与 `hint` 的偏差 ≤ 15 分钟（P0-1 的回归保护）

「三天入睡时刻不完全相同」这条断言在**任何**固定闹钟实现下都会红，
包括将来有人不小心把某个环节改回常量。

## 不要做的事

沿用前五轮全部禁止项，另加：

- **不要动第五轮的模型结构。** 两端 sigmoid 相乘、`cycleBoundary` 切点、迟滞方向
  都是对的。这轮只调锚点位置和生成提示词。
- 不要把 P0-1 的补偿量写成魔法常量。见上文。
- 不要用代码随机化来制造日程方差。见 P1-3。
- 不要为了让 `hint` 对齐而取消迟滞。迟滞是防清晨反复醒睡的，必须留着。
