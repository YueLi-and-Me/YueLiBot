## P0-1 · `MAX_ENERGY_SHIFT_MINUTES = 12` 把精力变成了装饰品

### 实测

固定 jitter、无互动，扫全精力区间：

```
energy=  5 → 入睡 22:40 (计划 22:50, -10min)
energy= 20 → 入睡 22:40 (-10min)
energy= 35 → 入睡 22:40 (-10min)
energy= 50 → 入睡 22:55 (+5min)
energy= 65 → 入睡 23:05 (+15min)
energy= 80 → 入睡 23:05 (+15min)
energy= 95 → 入睡 23:05 (+15min)

对比：无互动 → 22:55   刚聊完 → 00:10 (+80min)
```

**精力从 5 到 95 只移动 25 分钟，而且两端完全饱和**——精疲力尽（5）和状态不错（35）
的入睡时刻**一模一样**。同时「刚聊过」的影响是它的三倍多。

用户当初的原话是「**不是固定时间到点就睡，可以基于精力来进行判断**」。
现在精力的实际作用是 25 分钟、还带饱和——**这就是「到点就睡」加了个舍入误差。**

这和之前抓到的 `IDLE_GLANCE_AFTER_MS`、`wakeEnergyDelay` 是同一个形状：
常量在、逻辑在、测试绿，但在正常路径上根本产生不了可感知的差别。

### 这条是我的说明造成的

我在第六轮要求「实际入睡落在 `bedtimeHint` ±10 分钟」、第七轮又要求
「真实路径偏差 ≤30 分钟」。而原设计里 `energyShift = (50 - energy) * 1.8`
在两端能到 ±90 分钟——**这两个要求本身就是矛盾的**，你为了让断言通过只能钳制精力。
选择是合理的，被钳的对象选错了。

根子在于我把 `bedtimeHint` 当成了「实际入睡时刻的预测」。
它不是。**它是模型给的基线，状态修正本来就应该明显地改变它。**

### 改法

**1. 去掉 `MAX_ENERGY_SHIFT_MINUTES` 的钳制**，恢复精力对入睡锚点的完整影响。
如果 ±90 分钟太夸张可以调系数，但**必须保证全区间产生足够大的差异且不饱和**。

**2. 把验收改成两条，分别管两件事：**

- **基线对齐**（保留现有的固定 jitter 校准断言）：`energy = 50`、无互动、`jitter = 0.5`
  → 入睡/醒来落在 hint ±10 分钟。这条验证的是锚点补偿推导正确，仍然有价值。
- **状态位移足够大**（新增）：精力从低到高，入睡时刻要**单调后移**，
  且极端之间的差距 **≥60 分钟**。

**3. 废掉第七轮 P1-3 那条「真实路径偏差 ≤30 分钟」的断言。**
它是这次回归的直接成因。要给 jitter 加上界的话，**直接断言 jitter 项本身的幅度**，
不要用「总偏差」去间接约束——那会连带把所有状态输入一起锁死。

### 验收断言

```
★ 精力在全区间产生足够大且单调的入睡差异
   energy 从 10 到 90 每 10 一档 → 入睡时刻单调后移，
   两端差距 ≥60 分钟，且相邻档位不出现连续三档完全相同

★ 基线仍然对齐 hint
   energy=50、无互动、jitter=0.5 → 入睡/醒来偏差 ≤10 分钟

jitter 幅度有独立上界
   直接断言 jitter 项 ≤ ±15 分钟，不通过总偏差间接约束

第六轮的连续性不被破坏
   完整周期相邻 p 变化仍 ≤0.25
```

第一条必须能在改动前跑挂——现在 energy 5/20/35 三档结果完全相同。

## P0-2 · 内容质量不通过：她没有可过的日子

内容验收跑出来了，链路是通的，内容不合格。你自己的判断准确，**主动不重抽是对的**。

但你的诊断停在表面（「措辞同质」「主题都落在松弛」）。根因有四条，
其中一条是我的说明造成的。**照表面改提示词不会有用。**

### 根因一：「桌面」这个设定把她的世界压没了 ← 我的责任

数一下 16 个 slot 的动词：**翻笔记、听音乐、画画、整理素材、发呆**。就这五个。
再看措辞：「在桌面角落翻」「飘在桌面中央」「窝在桌面右下角」「对着桌面空白区域涂涂画画」。

模型不是懒，是**没得可写**。我在第四轮说明里写了：

> 不许出现：具体人名、地名、需要「真的出门」才成立的事（她是桌面上的角色，不是有身体的人）

这条写过头了。它把她锁进一个没有物品、没有场所、没有他人的真空里，
剩下能干的只有「整理」和「发呆」——所以三天必然长一样。

**《妹居物语》的角色是有房间、有生活的。** 约束的本意是不要让她声称做了
**可被证伪的现实动作**（「我今天帮你收了快递」——她做不到，说了就是穿帮），
而不是禁止她有生活。

**改法**：约束收窄成一条——**不要声称对现实世界做过任何事**。
除此之外她可以有完整的内心生活和虚构日常：想事情、纠结、期待、回忆、
计划、为一件小事高兴半天、跟自己较劲。这些都不会穿帮，而且才是陪伴感的来源。

### 根因二：没有跨天的连续性

三天是三次独立抽样，不是连着过的三天。真人的日子之所以是「不同的日子」，
不在于每天干的事不同，而在于**今天的事和昨天有关**——昨天画到一半的图今天接着画、
昨天想不通的事今天突然想通了、前天开始期待的事今天到了。

`DayPlan` 现在只传了昨天的 `theme` 和作息。**要传昨天的 `slots`**，
并明确要求：今天至少有一件事是**昨天的延续**，并在 `doing` 里说清楚是延续。

建议给 `DayPlan` 加一个字段承接这件事（例如 `carryOver`：一句「昨天没完成、
今天想接着做的事」），让连续性是结构化的，而不是指望模型自觉。

### 根因三：mood 词表全是同一种情绪

16 个 mood：松弛 / 悠闲 / 沉静 / 专注 / 欢快 / 好奇 / 随性 / 认真 / 安静 /
平和 / 惬意 / 轻松……**十四个是「平静愉快」的近义词。**

你说「mood 基本没有改变对话语气」——**机制没坏，是输入没有方差。**
同一种情绪换十四个词，语气当然不会变。

**改法**：提示词里明确要求一天之内 mood 要有起伏，且**必须允许负面**——
无聊、烦躁、有点低落、莫名兴奋、心不在焉、憋着一股劲。
陪伴角色永远心情很好是恐怖谷，不是治愈。

可以给一份情绪光谱作为参考范围，但**不要给固定词表让它挑**——那会变成新的模板。

### 根因四：丢了「刚醒」和「临睡」两个过渡段

「清晨刚醒」那格，`describeSchedule()` 输出的是
「你在桌面角落翻存的旧图文笔记……松弛」——**根本没提她刚醒**。
所以她回「刚有点困了」并不是模型不听话，是**注入里就没有这个信息**。

她 08:05 醒，第一个 slot 是 08:12「翻旧图文笔记」，中间没有任何过渡。
旧的固定 `SCHEDULE` 里是有 `wake` 段的（「刚醒，还在发呆」），
生成式日程把它弄丢了。

睡眠模型这边已经有 `drowsy`（睡前那格表现是合格的），**醒来这一侧没有对应物**。

**改法**：起床后一段时间内（建议 30~45 分钟）`describeSchedule()` 要注入
「刚醒」状态，和 `drowsy` 对称。可以由睡眠状态机给出，也可以要求生成时
必须包含一个紧接 `wakeHint` 的过渡 slot——倾向前者，因为实际醒来时刻是浮动的。

### 顺带一个观察

5~6 个 slot 铺满 16 小时清醒时间，等于**每件事持续三小时**。
「整理素材」整理三小时的人，被问起来是没有新东西可说的。
建议 slot 数量提到 8~10 个，让她的一天有更多变化点。这不是硬要求，
但如果改完前四条内容还是平，先动这个。

### 验收

仍然是**给人看的材料**，判据仍然是人读的。重跑一次，贴出：

- 连续三天完整 `DayPlan`（含新增的连续性字段）
- 六个时刻的 `describeSchedule()`，其中**必须包含「刚醒」那一格**
- 六次真实回答

判据：

- 三天读起来是**三个不同的日子**，且能看出**第二天接着第一天**
- 动词不再集中在「整理 / 翻 / 发呆」
- mood 有起伏，至少出现一次非正面情绪，且能在回答的语气里看出来
- 「刚醒」那一格她的回答要像刚醒的人

**依然不许重抽样。** 一次跑完就贴，不合格就报告不合格——
上一轮你这么做是对的，这一轮保持。

## P1-3 · `YUELI_NOW` 在渲染层没有生效

`src/renderer/diary.ts:14`：

```ts
function dayLabel(ts: number, now = Date.now()): string
```

主进程的时间已经统一到 `clock.ts`，但渲染层这里用的是**真实系统时间**。
注入 `YUELI_NOW=2051-07-15` 做内容验收时，日记里的「今天 / 昨天 / N 天前」
会全部按真实日期算，和窗口里其余内容对不上。

（`renderer/main.ts` 里那两处 `Date.now()` 是三秒 UI 超时，与业务时间无关，不用动。）

### 改法

`dayLabel` 的 `now` 由主进程随数据一起下发，渲染层不再自取。
渲染层本来就不该有时钟——第三轮为睡眠态定过这条规矩，日记这里漏了。

**验收**：注入 `YUELI_NOW` 后，日记的日期标签与注入时间一致。
