# 第九轮：连续性的信号给反了 + 情绪没落到语气上

上一轮**内容质量有实质提升**，先说清楚哪些通过了，不要在下一轮改坏：

- **精力钳制撤掉是对的**：10→90 的入睡跨度 150 分钟且全区间单调，
  jitter 在 ±12 分钟内，基线校准和跳变断言仍通过。这条恢复了「入睡由状态推导」的原意。
- **第一天的内容是合格的**。「纠结要不要给喜欢的那片云加个小翅膀，鼠标悬停在画笔上没动」
  「删了第三遍开头」「挑一个最呆的表情包，想下次他来的时候发给他逗他」
  —— 具体、有内心活动、有对他的期待、有留给明天的钩子。这是对的方向。
- **情绪有了真方差**，出现了烦躁、无聊、苦恼，不再全是「松弛」的近义词。
- **「刚醒」过渡段补上了**，六个时刻里有五个状态与回答一致。
- 日记时间改为接收主进程下发的业务时间，`YUELI_NOW` 的统一入口守住了。

**主动不重抽、如实报告不通过——连续两轮这么做，这个习惯请一直保持。**

## P0-1 · 传昨天的 slots，把「参考」变成了「模板」 ← 我的责任

### 证据

第二天和第三天复用了第一天几乎全部活动，而且是**带计数器地复用**：

```
删了第三遍开头  →  删了第四遍开头  →  删了第五遍开头
抠一个角色的名字 →  改角色名字     →  改角色名字改到第六个
脑补摆件偷偷动   →  编它偷偷跑出去 →  编它溜去摸键盘、碰出一串乱码
```

你的判断（「成了『承接整套昨天』而不是『承接一件主线』」）是准确的。
但根因不在提示词——**在我上一轮让你传昨天的 `slots`**。

模型拿到完整的昨日活动表，最自然的理解就是「这些都要接着写」。
那些递增的计数器恰恰说明它**在认真执行连续性**：如果一切都要延续，
连续性看起来就是这样。它没有偷懒，是我给的信号指错了方向。

### 你已经加的约束不够

「最多两段围绕 `carryOver`、至少六段必须是当天新展开」是**配额约束**，
它在和输入信号打架：一边把整张昨日表递过去说「参考这个」，
一边又说「不许照着写」。模型会在两者之间摇摆，产出不稳定。

**要改的是喂什么，不是喂完再限制。**

### 改法：把信号从「延续这个」翻成「避开这个」

生成时传三样，**不要传昨天完整的 slots**：

1. **`carryOver`** —— 唯一明确要延续的那条线。这个字段是对的，保留。
2. **昨天的 `theme`** —— 一句话，给基调参考。
3. **昨天做过的事的动词/对象摘要**，并明确标注为**「今天要避开重复的」**
   （例如：`昨天已经做过：便签写不出开头、抠角色名、脑补摆件、挑表情包`）。

第三样是关键：同样的信息，标签从「参考」换成「避开」，模型的行为会完全反过来。
这比配额约束可靠，因为它不需要模型在两个矛盾指令之间做取舍。

`carryOver` 本身也要收窄：它是**一条主线**，不是一份清单。
提示词里明确「只延续这一件事，其余全部是今天新开的」。

### 验收

重跑连续三天，判据：

```
★ 三天的活动对象不重复
   把三天所有 slot 的核心对象（便签 / 云图 / 摆件 / 表情包 / 小房子…）列出来，
   除 carryOver 那条主线外，跨天重复项为 0

carryOver 那条线要真的推进
   三天里能读出「昨天没画完 → 今天补院子 → 今天定了颜色画完」这样的进展

第一天的质感不能退化
   具体、有内心活动、有对他的期待、有留给明天的钩子
```

第一条能直接量出来，不靠主观判断。

## P0-2 · 情绪进了 prompt，但没落到语气上

### 证据

六个时刻里五个状态一致，唯一不一致的是「上午」那格：

```
注入：……刚删了第三遍开头，不知道该写什么内容。有点烦躁。
回答：「对着空白便签本发呆，不知道写什么。」
```

**读不出任何烦躁。** 而正面情绪是落地的——
「兴奋」那格她说「它刚偷偷跑出门啦」，「期待」那格说
「要不要换个亮一点的主题色等你？」，语气都对。

**正面情绪能落地，负面情绪落不了地。** 人设里并没有禁止负面表达
（`FORBIDDEN` 只管客服腔、动作描写、说教这些），所以这不是被人设压住的。

### 根因

`describeSchedule()` 把 mood 当成一个**光秃秃的形容词**贴在句尾：

```
……不知道该写什么内容。有点烦躁。
```

它告诉了模型「她的情绪状态是 X」，但**没告诉模型「这该怎么改变她说话」**。
正面情绪不需要指示也能自然带出来（开心的人说话本来就那样），
负面情绪需要具体的行为落点，否则模型会默认维持角色的基础调性。

### 改法：照人格四轴那套做

这个项目早就有正确的做法——**人格数值从不直接进 prompt，
而是映射成自然语言的行为指令**（`describePersona`）。mood 应该走同一条路。

不是：

```
有点烦躁。
```

而是：

```
你现在有点烦躁：说话会更短，容易岔开话题，可能会抱怨一句手上这件事，
但不会冲他发脾气。
```

给几种典型情绪各写一条行为映射（烦躁 / 无聊 / 低落 / 兴奋 / 期待 / 苦恼），
落点要具体到**句长、是否主动挑话题、会不会抱怨、会不会走神**这种层面。

⚠ 但**不要给模型一份固定的 mood 词表让它挑**——上一轮刚从「十四个近义词」
里出来，回到固定词表就是退回去。做法是：生成侧继续自由产出 mood 词，
`describeSchedule()` 侧做映射；**映射表没命中的词，就按情绪的正负和强度
走一条通用的行为指令**，不要因为没命中就退回光秃秃的形容词。

### 验收

```
★ 负面情绪的那一格，回答的语气能读出来
   注入一个负面 mood 的时刻 → 她的回答在句长或态度上明显区别于正面时刻

映射表没命中的 mood 也会给出行为指令
   传一个词表里没有的情绪词 → describeSchedule 输出仍包含行为落点，
   不是光秃秃一个形容词
```

第一条仍然是人读的判据，第二条可以断言。

## P1-3 · 格式不稳定

第三天的 slots 全部以「我」开头，前两天没有：

```
第一天：翻着桌面文件夹里存的旧风景图，正纠结……
第三天：我盯着桌面悬浮的小太阳图标，正琢磨……
```

`describeSchedule()` 会在前面拼「此刻你……」，所以第三天会拼成
「此刻你我盯着……」这类句子。小问题，但会直接进 prompt。

在校验层归一化（去掉开头的第一人称代词），不要指望提示词每次都对。
加一条断言：`doing` 以「我」开头时会被清掉。
