# 生图管线

从参考图跑出一整套角色立绘差分素材。**你只需要做两件事：定稿底图、看图挑好坏**，不需要写提示词，也不需要碰 ComfyUI。

## 命令传参约定

Windows 下 `npm run xxx -- --flag` 会被 npm 当成自己的配置吞掉（实测 npm 11 + PowerShell，加引号也没用）。所以：

- **无参数**的命令用 `npm run`
- **带参数**的命令用 `npx tsx scripts/sprite/<脚本>.ts --flag`

## 一次完整流程

### 0. 配置

复制 `.env.example` 为 `.env` 填好 Key。`.env` 已在 `.gitignore` 里，**不要把 Key 贴进聊天、截图或提交记录**。

```bash
npm run sprite:test
```

冒烟测试会跑**两条**路径：文生图（`generate`）和指令编辑（`edit`）。后者是管线主力——27 张里 23 张走它——并且会检查它有没有改变画布尺寸（尺寸一变，整套对齐的前提就没了）。

必须先跑通这个再往下走。失败了跑诊断（仅 Gemini）：

```bash
npm run sprite:diagnose
```

三步定位问题：出网 → Key 有效性 → 目标模型可用性。

> Gemini 的图像模型**免费层额度是 0**（报错里会看到 `limit: 0`），必须在 AI Studio 给项目开通付费层。
> 方舟（Seedream）无此问题，实名即用。

### 模型选型（实测数据）

同一组「只把帽子改成红色」的指令编辑，两个方舟模型的表现：

| 指标 | Seedream 4.0 | **5.0 Pro** |
|---|---|---|
| 单张耗时 | 5–7s | 62–67s |
| 宽度漂移 | +43px (3.4%) | **-3px (-0.3%)** |
| 高度漂移 | +21px (1.0%) | **0px (0.0%)** |
| 顶部偏移 | -8px | **0px** |
| 判定 | ⚠ 明显漂移 | **✓ 轮廓几乎不变** |

一致性是素材质量的天花板，速度只是等待时间。所以管线**按阶段自动换档**：

- **底图候选**用 4.0 —— 这步本来就要 4 张各不相同的图，一致性毫无意义，没必要付 10 倍等待
- **表情差分**用 5.0 Pro —— 零漂移，全套 27 张按并发 2 算约 15 分钟

想手动指定：两个脚本都支持 `--model <模型ID>`。在 `.env` 里填 `ARK_IMAGE_MODEL` 则两阶段都用它，失去自动换档。

> 「解锁图层自由」不等于能直接输出透明背景。实测五种写法（提示词要求、`transparent`、`background`、`transparent_background` 等参数）全部返回不带 alpha 的 JPEG，未知参数被静默忽略。`rembg` 这步省不掉。

### 1. 底图

```bash
npx tsx scripts/sprite/base.ts --ref ./ref.png --desc "银发蓝瞳，水母主题连衣裙，气质温柔"
```

跑 4 张候选。挑图时看四件事：

1. 全身完整入画，头顶和脚都没被裁掉
2. 正面站姿、双臂自然下垂 —— 姿势越简单，后续改表情越不容易连带改动身体
3. 背景干净纯白，无多余元素和水印
4. **服装完整** —— 方舟对**输入图片**也做内容审核，衣着过少的底图会在下一步被 `InputImageSensitiveContentDetected` 全量拦死

第 4 条是实测踩出来的：`--desc` 写得太模糊（且没给 `--ref`）时，模型会画出没穿衣服的人体基础模板，底图本身看着没问题，但拿它做差分会 100% 被拒。**务必带 `--ref` 参考图，并在 `--desc` 里写清楚服装。**

```bash
npx tsx scripts/sprite/base.ts --pick 2
```

底图是整条管线的地基，后面 23 张差分全部以它为基准做指令编辑，**它的质量直接决定一致性上限。宁可多跑几轮。**

### 2. 批量生成

```bash
npm run sprite:gen
```

产出 16 表情 + 4 闭眼差分 + 3 嘴型。

- 并发默认 2，429 自动指数退避
- **断点续跑**：每完成一项立刻落盘，Ctrl-C 后重跑只补缺的，不重复计费
- 只跑指定条目：`npx tsx scripts/sprite/gen.ts --only face/shy,face/cry`
- 全部重跑：`npx tsx scripts/sprite/gen.ts --force`

### 3. 挑图（管线里最值钱的一步）

```bash
npm run sprite:preview
```

一致性漂移肉眼扫不出来——头发丝、衣褶、腰线的细微变化，单看一张图完全正常，切换时才发现在抖。所以核心是 **diff 模式**：跟底图逐像素比，改动区域高亮，模型偷偷改了衣服立刻现形。

快捷键：`← →` 切换　`D` 差异　`F` 闪烁　`S` 并排　`X` 标记不合格　`Enter` 保存

- **差异**：改动像素占比 > 12% 会直接警告「八成动了脸以外的地方」
- **闪烁**：A/B 快速交替，位置偏移在闪烁下极其显眼，静态对比反而看不出来

标记后保存，再跑一次 `npm run sprite:gen` —— 被标记的条目会带着**具体问题描述**重新生成（比单纯换 seed 重跑有效得多）。

### 4. 后处理

```bash
npm run sprite:process
```

抠透明背景 → 对齐 → 出 `manifest.json`。

**这一步做三件事，每一件都是实测逼出来的：**

1. **位置归一**：按 alpha 包围盒把所有图对到同一画布、同一锚点（头顶中心）
2. **缩放归一**：以底图高度为基准等比缩放
3. **脸部烘焙**：把所有表情的脸贴到**同一具身体**上

**第 2 条**：Seedream 4.0 做一次指令编辑，角色整体会放大约 3.4%（5.0 Pro 只有 0.3%）。位置能救，缩放救不了，切表情时角色会一大一小地「呼吸」。脸变了但身高不该变，所以按高度归一是安全的。

**第 3 条最关键。** 实测 5.0 Pro 虽然轮廓几乎不变，但会把布料褶皱、发丝走向、尾巴形态**整体重画一遍**——身体区域逐像素差异高达 18~20%。静态对比完全看不出来（同款不同笔触），可运行时整图切换表情，人眼对闪变极其敏感，整个身体会「滋啦」一下。

所以后处理直接把身体统一掉：底图是唯一的那具身体，各表情只贡献脸部区域，用羽化椭圆遮罩融合（硬边会在交界处露接缝）。烘焙后所有表情的身体逐像素一致，切换零闪烁。

脸部区域优先自动求（眼区 ∪ 嘴区再外扩），检测有两道防线——只在头部搜索、只找差异最密集的一块，而不是所有差异的包围盒。

**但自动检测有它救不了的情况，别指望它百分百可用。** 它依赖「五官差异密度显著高于身体」这个前提，而长发角色会直接推翻它：实测一个及腰长发的角色，头发每次都被重画，「眼部」差异的峰值落在 y=711（34% 高度处，也就是胸口位置），眼睛那点信号完全被淹没。检测结果不合理时会被 `plausible()` 拦下并丢弃，然后跳过烘焙。

这时手填坐标，一次就好：

```bash
npx tsx scripts/sprite/process.ts --face 280,210,210,200 --eyes 295,235,180,65 --mouth 345,320,90,50
```

坐标怎么量：把 `assets/character/<name>/face/normal.png` 裁一块出来，叠个带刻度的网格看一眼即可。**注意脸不一定在画布中心**——头发向一侧铺开会把内容包围盒的重心带偏（实测偏了约 60px）。

实测效果：手填后身体差异从 18~20% 降到 **0.0%**，只剩头部 1.1~2.8%。

关掉：`--no-rescale` / `--no-bake`

一致性报告比较的是**归一之后**的残余差异。

### 单独体检两张图

```bash
npx tsx scripts/sprite/consistency.ts <图A> <图B>
```

量化轮廓宽高、顶部、中心的偏移和差异像素占比。用来评估某个 provider 或某组指令做差分的稳定性——肉眼看「差不多」的两张图，轮廓可能已经差了百分之几。

分级：`<1%` 很稳　`<3%` 对齐后看不出　`<8%` 有呼吸感　`≥8%` 切换会明显抖。

需要 `rembg`（动漫立绘用 `isnet-anime` 模型，效果远好于任何阈值方案）：

```bash
pip install "rembg[cli]" onnxruntime
```

装不上可以先用降级方案，但它会把白色服装和高光一起吃掉：

```bash
npx tsx scripts/sprite/process.ts --naive
```

## 不烧配额的自检

```bash
npm run sprite:fixture          # 造合成素材（模拟 AI 生图的像素漂移）
npm run sprite:process:fixture  # 跑后处理
npm run sprite:preview:fixture  # 看预览页
```

合成素材里有一张 `face/cry` 故意把身体加宽，用来验证一致性报告能否抓出「模型改了身体」。

## 产物结构

```
assets/character/<name>/
  raw/                 生图原始产物（白底、未对齐）—— 已 gitignore
    base-1..N.png      底图候选
    base.png           定稿底图
    face/ eyes/ mouth/
    state.json         已完成条目，支撑断点续跑
    review.json        预览页标记的重跑清单
  base.png             最终产物（透明背景、已对齐）
  face/ eyes/ mouth/
  manifest.json        运行时消费的清单
```

`manifest.json` 是渲染层唯一需要读的文件——`SpriteCharacterView` 拿它就能工作，不需要知道图是怎么生成的。

## 换 provider

改 `.env` 一行即可，代码不用动：

```bash
SPRITE_PROVIDER=seedream    # 或 gemini
```
