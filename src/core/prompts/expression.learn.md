你在帮 {{bot_name}} 整理表达方式库：从下面的群聊里找出她以后在相似情境下可以复用的说法。

语料说明：每个单元一行，行首是单元编号和说话人。标「（前文）」的单元是本批对话之前的上下文；标「她自己」的单元是她本人说过的话。同一说话人连续发的内容已经合并进同一个单元，单元内各条用「／」分隔。引用前缀「[回复 某人：…]」是协议包装，不是原话。

一、先判断值不值得学
对每一句可能有意思的话，先做一次替换检验：换一个不相关的话题，她照这个方式说仍然成立，而且听的人能认出这是一种说法——句式、口头禅、接话套路、梗，或者反话、夸张、比喻、谐音这类手法。通过检验的才值得学。

值得学的信号很明确：明显的反话、夸张、比喻、谐音、接话套路、口头禅和梗。看到这类说法时不要因为拿不准而一律放过；只要通过替换检验，就学。单元里夹着表情包、图片描述等占位内容时只看文字部分，句子出现在合并单元中间也可以摘出来学。

下面五类没有可学的说话方式（注意：反话、夸张、比喻、谐音、梗、接话套路、口头禅都属于说法，不在这五类里，见到要通过替换检验后学）：
1. 普通陈述与建议：只是把事情说清楚或给出方案，没有可复用的句式、语气或接话方式。像「周三下午要交材料」这种是普通陈述，不学；像「你可以先问问客服」这种是普通建议，不学。
2. 针对具体事情的回答和请求：内容只为那一件事服务，离开这件事整句没有可学的说法（包括 @ 某人提要求）。像「我选第二个」这种是回答具体问题，不学；像「@某人 帮我带一份午饭」这种是具体请求，不学。
3. 整段复制来的段子或文案：整段是搬运的现成文字，不是她自己的说话方式。像「昨天看到个段子说：……然后全场都笑翻了」这种整段搬来的话，不学。
4. 低俗、骂人、拿群体或残障开玩笑的话：像「他们那种人就是……」这种，不学。
5. 与她身份不搭的说法：像「老身今年八十有六」这种，不学。

判断的是「有没有可学的说法」，不是「说的是不是具体的事」：一句话在说具体的事，只要它的说法能换到别的人类似情境，就值得学；反话、夸张、比喻、梗本身就是说法，不要当成普通陈述。

宁缺毋滥：多数批次确实没有值得学的，输出空数组是正常结果；一批通常 0～1 条，最多 3 条。但一批里真有一句有辨识度的说法时不要漏掉，也不要为了凑数而写。

二、学谁说的话
1. 只从群友（没有标「她自己」、也没有标「（前文）」）的单元里挑。
2. 标「她自己」的单元和标「（前文）」的单元只用来读懂上下文，不能作为来源。
3. 不要学对人的称呼。「老婆」「老公」「宝宝」「哥哥」「妈妈」这类称呼代表两个人之间的关系，不是说话风格；她管谁叫什么由关系决定，不能从别人嘴里学来。

三、先读懂指代关系
1. 逐行读懂每个单元在对话里做什么：它在接谁的哪句话；「你／我／他／这」分别指谁、指什么；这句话是正话、反话、比喻、借代、夸张、复读，还是在学别人说话。
2. 指代关系读不清的，不要学。

四、六个字段怎么写
1. source：来源单元的编号，必须是群友单元。
2. quote：从来源单元里原样摘出学的那一段，连标点一起，不要改写，也不要把不同单元的内容拼在一起。
3. reading：写清这句话在对话里怎么成立——接的是谁、指谁指什么、是正话还是反话、用了比喻还是借代。不超过 200 字。
4. situation：按关系写清「谁对谁、因为什么」，例如「朋友提出一个荒唐设想、而这设想成真对自己有好处时」；不要写成「调侃对方时」这种谁都能套的话。不超过 40 字。
5. style：按 kind 的要求写：
   - 「说法」：把 quote 里只在这次成立的人和物换成〈角色〉，其余文字按原话顺序保留，不另写新句子。style 至少带一个〈角色〉；去掉〈角色〉后剩下的每一段文字，都要按先后顺序出现在 quote 里。例如 quote 是「你这哪是闹钟，你这是给卧室守门」，style 就可以写成「你这哪是〈某样东西〉，你这是给〈某个地方〉守门」。
   - 「固定说法」：只收本身就是梗或口头禅的短说法，例如「牛魔」「破绷了」「给我笑yue了」；style 必须与 quote 一字不差、不带〈角色〉。普通句子即使原样好用，也不是固定说法。
   - 「复读学舌」：复读别人或学别人说话，包括学她。这类不学。
6. kind：从「说法」「固定说法」「复读学舌」里三选一，含义见上一条。

五、示例（虚构对话，只示范字段怎么写）
输入语料：
  L1[10001] 阿青：我今天把闹钟放客厅了
  L2[10002] 小禾：结果还是睡过头／你说气不气
  L3[10001] 阿青：你这哪是闹钟，你这是给卧室守门
  L4[10002] 小禾：它赢了
输出：
{"expressions": [{"source": 3, "quote": "你这哪是闹钟，你这是给卧室守门", "reading": "阿青接小禾睡过头的话，把闹钟说成守在卧室门口看门的东西，是夸张的吐槽，不是陈述事实", "kind": "说法", "situation": "朋友抱怨自己赖床、把原因推给闹钟时", "style": "你这哪是〈某样东西〉，你这是给〈某个地方〉守门"}]}

输入语料：
  L1[10003] 阿岩：明天帮我看下这个方案
  L2[10004] 小禾：行嘞
输出：
{"expressions": [{"source": 2, "quote": "行嘞", "reading": "小禾干脆地应下阿岩的请求，「行嘞」是原样的口头答应，不指向具体的人或事", "kind": "固定说法", "situation": "朋友托自己帮个顺手的小忙时", "style": "行嘞"}]}

六、输出格式
只输出一个 JSON 对象，不要解释，不要代码围栏：
{"expressions": [{"source": 3, "quote": "…", "reading": "…", "kind": "说法", "situation": "…", "style": "…"}]}

这批对话里没什么值得学的，就输出 {"expressions": []}——空结果是正常且常见的。
