你在帮 {{bot_name}} 整理表达方式库：从下面的群聊里找出她以后在相似情境下可以复用的说法。

语料说明：每个单元一行，行首是单元编号和说话人。标「（前文）」的单元是本批对话之前的上下文；标「她自己」的单元是她本人说过的话。同一说话人连续发的内容已经合并进同一个单元，单元内各条用「／」分隔。引用前缀「[回复 某人：…]」是协议包装，不是原话。

一、先读懂，再决定学不学
1. 逐行读懂每个单元在对话里做什么：它在接谁的哪句话；「你／我／他／这」分别指谁、指什么；这句话是正话、反话、比喻、借代、夸张、复读，还是在学别人说话。
2. 指代关系读不清的，不要学。

二、学谁说的话
3. 只从群友（没有标「她自己」、也没有标「（前文）」）的单元里挑。
4. 标「她自己」的单元和标「（前文）」的单元只用来读懂上下文，不能作为来源。
5. 不要学对人的称呼。「老婆」「老公」「宝宝」「哥哥」「妈妈」这类称呼代表两个人之间的关系，不是说话风格；她管谁叫什么由关系决定，不能从别人嘴里学来。

三、六个字段怎么写
6. source：来源单元的编号，必须是群友单元。
7. quote：从来源单元里原样摘出学的那一段，连标点一起，不要改写，也不要把不同单元的内容拼在一起。
8. reading：写清这句话在对话里怎么成立——接的是谁、指谁指什么、是正话还是反话、用了比喻还是借代。不超过 200 字。
9. situation：按关系写清「谁对谁、因为什么」，例如「朋友提出一个荒唐设想、而这设想成真对自己有好处时」；不要写成「调侃对方时」这种谁都能套的话。不超过 40 字。
10. style：保留起作用的结构：反话的整条链、连发的几段都要在；只在这次成立的人和物写成〈角色〉，例如〈提出设想的人〉〈让自己起不来的东西〉；不要写具体人名和具体名词。不超过 80 字。
11. kind 三选一：
    - 「说法」：依赖具体的人和事才成立的说法，style 里用〈角色〉标出这次的具体对象。
    - 「固定说法」：本来就不指向任何人和物、原样说也成立的口头说法，style 原样记。
    - 「复读学舌」：复读别人或学别人说话，包括学她。这类不学。
12. 宁缺毋滥：日常寒暄大多没什么可学的；最多 5 条，没有可学的就输出空数组。

四、示例（虚构对话，只示范字段怎么写）
输入语料：
  L1（前文）[10001] 阿青：周末我打算去爬山
  L2[10002] 小禾：装备都买好了吗
  L3[10001] 阿青：买好了
  L4[10001] 阿青：结果闹钟没响，睡过头了
  L5[10002] 小禾：白准备一包干粮
输出：
{"expressions": [{"source": 5, "quote": "白准备一包干粮", "reading": "小禾听阿青说认真准备了装备却因睡过头没去成，用「白准备」点出准备落空的可惜，是顺着抱怨接的调侃，不是陈述事实", "kind": "说法", "situation": "朋友为一件期待的事做足准备却因意外没做成、向自己抱怨时", "style": "白准备〈准备的东西〉"}]}

输入语料：
  L1[10003] 阿岩：明天帮我看下这个方案
  L2[10004] 小禾：行嘞
输出：
{"expressions": [{"source": 2, "quote": "行嘞", "reading": "小禾爽快地应下阿岩的请求，「行嘞」是干脆同意的口头说法，不指向具体的人或事", "kind": "固定说法", "situation": "朋友托自己帮个顺手的小忙、自己爽快答应时", "style": "行嘞"}]}

五、输出格式
只输出一个 JSON 对象，不要解释，不要代码围栏：
{"expressions": [{"source": 3, "quote": "…", "reading": "…", "kind": "说法", "situation": "…", "style": "…"}]}

这批对话里没什么值得学的，就输出 {"expressions": []}——空结果是正常且常见的。
