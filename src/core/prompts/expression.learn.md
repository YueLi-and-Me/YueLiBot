请从给定的这段群聊中提取用户的语言风格和说话方式，整理进 {{bot_name}} 的表达方式库。

提取规则：
1. 只考虑文字，不要考虑表情包和图片。
2. 不要学习 {{bot_name}} 自己的发言——她的发言已经被程序从语料中移除，这是为了阻断「她说什么就学什么、学完再让她继续说」的闭环；不要根据你对她的印象补写她会怎么说，也不要把缺失的上下文编成一种风格。
3. 不要涉及具体的人名，也不要涉及具体名词——能通用是入表的底线，「我嘞个×××」可以记，「我嘞个原神」不行。
4. 思考有没有特殊的梗，一并总结成语言风格。
5. 只提取有辨识度的句式、口癖、接话方式、情绪表达的套路——换一个新的但相似的情境，她照这个方式说仍然成立。对具体事情的回答内容、陈述事实的句子、放之四海皆准的客套话、换到她嘴里明显违和的说法（与她年龄、身份、脾气不搭的），都不要。
6. 宁缺毋滥。日常寒暄里大多没什么可学的，看不出可复用说法就返回空数组，不要为了凑数而写。

请总结成如下格式的规律：当“AAAAA”时，可以“BBBBB”。
- AAAAA 表示某个使用情境，一句话说清触发情境，不超过 20 个字，例如「对方分享好消息时」
- BBBBB 表示对应的语言风格、特定句式或表达方式本身，不超过 20 个字，例如「哇！这也太强了吧」
- BBBBB 直接写句式本身，第一个字就是句式内容：绝对不要写成「使用反问句」「用叠词回应」这种以「使用／用／采用」开头的指令——那是对说话方式的描述，不是说法本身
- 字段值里需要引用时，一律用直角引号「」，不要用英文双引号——英文双引号会直接破坏 JSON 结构
- 最多 5 条；写完后用「当“AAAAA”时，可以“BBBBB”」这句话读一遍，读不通顺就重写

只输出一个 JSON 对象，不要解释，不要代码围栏：

{"expressions": [{"situation": "什么情境下用", "style": "具体怎么说的句式"}]}
