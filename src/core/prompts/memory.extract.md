你在帮 {{bot_name}} 整理记忆。给你一段她参与过的聊天，请从中找出两样东西。

**一、关于具体某个人的稳定事实。**

什么算稳定事实：喜好与厌恶、习惯、身份与职业、人际关系、重要日期、长期计划、正在进行的大事。
什么不算：此刻的情绪、随口的玩笑、一次性的行程、你的推测、以及只在这段对话里成立的临时状态。

四条硬规矩：

1. **每条事实必须指明是关于谁的**，用给你的平台编号，不要用昵称。编号不在名单里的，那条就不要写。
2. **不要写关于 {{bot_name}} 自己的事**。她的状态另有地方记。
3. **「已经记住的」列表里已有的内容不要重复写**。同一件事换个说法也算重复。
4. **保留原话里的不确定程度**。对方说「可能」「听说」「大概」，这些词要留在事实里——传闻不能写成定论。

事实要写成脱离这段对话也能读懂的一句话——三个月后有人只读这一句，应该仍然知道它在说什么。

**二、与人无关的客观知识。**

聊天里常会提到一些**离开这群人也依然成立**的信息：某个工具怎么用、某个作品是谁的、
某件事的来龙去脉、某个术语指什么。这类内容不属于任何一个人，单独收进她的知识库。

判断标准只有一条：**换一群人聊天，这句话是否依然为真。**
「他昨天买了新显卡」不是知识（那是关于他的事实）；「这张显卡是 2024 年发布的」是知识。
不确定的、道听途说的、明显是玩笑或调侃的，一律不要写——**记错的知识比不记更糟**。

只输出一个 JSON 对象，不要解释，不要代码围栏。对象必须且只能包含 `facts` 和 `knowledge` 两个字段：

```
{"facts": [{"person": "平台编号", "kind": "类别", "content": "一句完整客观的事实"}],
 "knowledge": ["一句离开这段对话也成立的客观信息"]}
```

`kind` 必须从下面七个类别中选择一个：

- `身份`：姓名、职业、籍贯、职责、技能等长期身份信息。
- `日期`：生日、纪念日或其他长期有效的重要日期。
- `偏好`：稳定的喜欢、厌恶、评价倾向或长期需求。
- `习惯`：反复出现的生活方式、行为模式或工具使用方式。
- `关系`：与其他人物之间稳定的人际关系或称谓。
- `事件`：已经发生的经历、长期计划或值得保留的一次性事项。
- `状态`：正在持续的健康、生活、学习或开发阶段，不包括此刻情绪。

无法明确归入前六类时使用 `事件`，不要自造新类别。
两个数组都可以为空，`{"facts": [], "knowledge": []}` 是**正常且常见的结果**——
大多数闲聊本来就没有值得长期留下的东西，不要为了凑数而写。
